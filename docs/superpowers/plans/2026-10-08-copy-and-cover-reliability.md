# Copy and Cover Reliability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Repair Android copy state/errors, isolate root-level book copies into metadata-named folders, and make Open Library covers load before and after publication.

**Architecture:** Keep connected runtime identity independent from destination persistence, centralize copy-start result messaging, generate root-book destination folders in the server manifest builder, validate provider redirects per hop, and revise authenticated cover models with the catalog generation. Reuse existing sanitizers, DTOs, clients, and worker scans.

**Tech Stack:** Kotlin, Jetpack Compose, Coil 3, OkHttp, Go, PostgreSQL-backed catalog, JUnit, Go testing.

## Global Constraints

- Work in the current checkout; do not create a worktree.
- Preserve unrelated changes in `deploy/compose.hybrid.yml`, `docs/roadmap.md`, `.codex-remote-attachments/`, and `deploy/.state/`.
- Enriched root-book folder format is `Author - Title (Year)`, omitting missing components and using the first author.
- Fall back to the safe audio filename stem when enriched metadata is unusable.
- Never expose BookBox credentials to provider cover hosts.
- Do not publish local attachments, deployment state, secrets, or unrelated uncommitted changes.
